The Onboarding Interview

How a new Meta-System install is meant to set itself up: through a plain conversation, not a settings screen.

Read this first

This page describes how the interview is designed to work. It is a draft and has not been used in a real install. It is not connected to 3.7 yet, so a test install today will not run it. The current status section at the bottom lists exactly what is missing.

What it is

The onboarding interview is a conversation. The new user's own copy of Claude runs it the first time the system is installed. There is no separate installer program: the interview is the installer. By the end of it, the system exists on the user's computer, built around what they said.

Claude already knows what a working Meta-System looks like, because it runs inside one. The person installing it doesn't need to know any of that. Their job is to talk about themselves and their work. Claude's job is to turn that into a finished, working setup.

Two paces

The interview opens by offering a choice, in roughly these words:

I can walk through this step by step, or if you'd rather just tell me about yourself and your work and let me handle the rest, that's fine too.

Step by step means more explanation and a longer conversation. "Tell me about yourself and I'll handle it" means less explanation and a shorter one.

The pace changes how much gets explained. It never changes who designs the system. Choosing the fast path does not hand the user any technical decisions, and the slow path doesn't either. That holds however technical the user is. The point isn't whether they could decide. The design already carries a lot of accumulated judgment, and making every new user work it out again from scratch is exactly the waste the system exists to avoid.

The five questions

All five are asked in plain language. None of them is a technical interview.

Question one

Who are you, and what do you do?

Your work, your goals, and what you'd want an assistant to already know so you don't have to repeat it every session. This becomes your identity file.

Question two

Where should this live?

In your home folder, or in a folder of its own. This one really is your call, and it isn't technical. (See the status notes: 3.7 currently fixes this location, so the question needs updating.)

Question three

What's already in motion?

Your existing projects, work, and commitments. This tells Claude how big to make the project list and what should already be in it on day one. It is not asking whether to build the project list at all. That gets built either way.

Question four

What should I always check with you before doing?

Your hard boundaries, asked the way you'd ask a person, not the way you'd configure a system. Common answers are saving work permanently, deleting anything, or sending anything outside your computer, but it is whatever you name. Your answer becomes this install's own standing rules.

Question five

How would you like this to feel day to day?

More explanation or less. More checking in or less. This sets how the system talks to you. It is not a menu of features.

What you are never asked

The user never chooses the architecture. There are no questions about where data is stored, what format it's in, which modules to include, or any other implementation detail. Claude makes those calls itself, the same way it would for any other part of the build, without presenting them as choices you need an opinion on.

The check before building

Before writing anything to disk, Claude summarizes what it is about to build: where it will live and what it will contain. Then it waits for a plain go-ahead.

This is a courtesy check, not a design review. It confirms Claude understood you correctly. It isn't asking you to approve the architecture.

What it builds

After the go-ahead, it builds the complete pattern, for real, on disk:

  • A CLAUDE.md file at the chosen location, in your own terms. It's the instruction page every Claude session reads first. It is about a page long but structurally complete: who you are, your standing rules, and what is being tracked.
  • An identity file, from your answer to question one.
  • A project registry, the list of what you're working on.
  • A decision log, a record of decisions and the reasons for them.
  • An idea bank, a place to drop ideas that arrive at the wrong moment.

The registry, decision log, and idea bank are kept in a small database on your computer, not in text files that get unwieldy as they grow.

It builds all of it even if you're unsure what you'll track. If you don't have clear answers yet, you get the complete system with empty, ready structures, not a smaller one. You don't have to know what you'll need before you have it. A system that starts out as almost nothing has nothing underneath it to improve.

How it ends

The session ends with Claude telling you plainly what now exists, where it is, and what to do next. Usually that is simply to start talking to it about your work.

The design has one firm rule here. If Claude said it would build something, that thing must exist on disk before the session ends. A good conversation that never got written down doesn't count as an install.

Current status

Verified 2026-09-25

Where the onboarding interview actually stands
  • It is a draft. Its only test so far was a demonstration run with a fictional user, a freelance designer, against its own storage code. It has never run as a live session with a real person.
  • It is not connected to 3.7 yet. It saves what it learns to its own separate database file. 3.7's screens read from a different database and a different idea-bank file. Anything the interview built would not show up in the 3.7 app.
  • Claude won't find it on a 3.7 install yet. It isn't in a folder where Claude Code looks for skills.
  • Nothing starts it automatically on first run.
  • Its wording still names the original owner and needs to be made generic.
  • It asks where to install, but 3.7 already fixes the install location. Question two needs to change to match.
  • It assumes a blank computer. 3.7 already ships with baseline files, which the interview would need to extend rather than overwrite.

What this means for a test install: expect to set up without the interview. The rest of 3.7 can be tested on its own, and the user guide describes it. No date has been set for connecting the interview.
