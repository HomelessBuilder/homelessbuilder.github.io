Career: résumé reference

What a qualified candidate's résumé looks like

Prepared Oct 21, 2026. Composite bullet points for Cloud Infrastructure Engineer and AI Engineer roles, drawn from the requirements in the two job-lead lists. Highlighted [brackets] are placeholders for a real candidate's own figures. Counts show how many postings asked for each area.

Cloud Infrastructure Engineer

Built from the 8 confirmed postings on the cloud infrastructure lead list. The 6 listed-only roles weren't opened, so they aren't reflected. See the lead list.

Summary line

Cloud infrastructure engineer with [6+] years building and running production AWS and Kubernetes environments as code, with security and compliance built into the platform from the start.

Infrastructure as Codeall 8

  • Wrote and maintained Terraform modules provisioning [VPCs, EKS clusters, IAM, RDS] across [N] AWS accounts, replacing manual console changes and cutting environment build time from [days] to [hours]
  • Automated server configuration and patching with Ansible across [N] Linux and Windows hosts

Kubernetes and containers6 of 8

  • Designed and operated production Kubernetes clusters (EKS, OpenShift) running [N] services, packaged with Helm and deployed through GitOps with Argo CD
  • Containerized [N] legacy applications with Docker and migrated them onto Kubernetes with zero downtime

CI/CD pipelines6 of 8

  • Designed GitLab CI and GitHub Actions pipelines covering build, test, security scan and deploy, cutting release time from [X] to [Y]
  • Managed build artifacts and container images in Artifactory and Amazon ECR

AWS architecture and security6 of 8

  • Built multi-account AWS environments with AWS Organizations, service control policies (SCPs) and least-privilege IAM roles
  • Turned on and tuned CloudTrail, GuardDuty, Security Hub and AWS Config, fixing [N] high-severity findings
  • Designed VPC networking: subnets, security groups, network ACLs, Transit Gateway, VPN and Direct Connect to on-premises networks

Networking and identity4 of 8

  • Managed DNS, routing and site-to-site VPN between cloud and on-premises networks
  • Set up single sign-on (SSO) by federating Entra ID / Active Directory into the cloud using SAML and OIDC

Observability4 of 8

  • Built monitoring and alerting with CloudWatch, Prometheus and Grafana (or Datadog), cutting mean time to resolve incidents by [X%]
  • Ran capacity planning and cost reviews that saved $[X] a year

Linux and scriptingall 8

  • Administered RHEL and Ubuntu fleets of [N] hosts, hardened against CIS Benchmarks and DISA STIGs
  • Wrote Python and Bash tooling to automate [provisioning, backups, compliance reports]

Compliance and government4 of 8

  • Supported FedRAMP / NIST 800-53 controls in AWS GovCloud, including air-gapped deployments
  • Held a [Public Trust / Secret / TS/SCI] clearance

Client-facing workGuidePoint, contract roles

  • Ran cloud security assessments for [N] clients and delivered written findings, remediation plans and architecture diagrams

Skills section

AWS (EC2, S3, VPC, IAM, EKS, EFS, CloudWatch), Azure, GCP, OCI · Terraform, CloudFormation, Ansible · Kubernetes, Docker, Helm, Argo CD, OpenShift · GitLab CI, GitHub Actions · Prometheus, Grafana, Datadog · Python, Bash, Go · Linux (RHEL, Ubuntu), Windows Server

Certifications named: Required somewhere: AWS Cloud Practitioner (GuidePoint), Security+ (Marlin). Preferred: AWS Solutions Architect Associate, AWS Security Specialty, CCSK. Common in the field though none of these 8 named them: CKA, HashiCorp Terraform Associate.

Experience: Most ask for 3 to 8 years. GuidePoint is the exception: it accepts 1 year, and hands-on labs count toward it.

AI Engineer

Built from the 9 confirmed postings on the AI engineering lead list that showed requirements. RevStar's requirements didn't load and the 3 Workday listings weren't opened. See the lead list.

Summary line

AI engineer with [N] years of software experience who builds production LLM and agent systems, measures their quality with evaluations, and deploys them on cloud infrastructure.

Python and backend services6 of 9

  • Built async Python services in FastAPI that stream LLM responses to clients over server-sent events (SSE), serving [N] requests a day at a p95 latency of [X ms]
  • Wrote typed, tested Python with Pydantic models enforcing contracts between services and LLM outputs

LLM applications and agents5 of 9

  • Designed and shipped a multi-step agent system with [LangGraph / Anthropic SDK / OpenAI Agents SDK] that automated [workflow], cutting manual handling time by [X%]
  • Built tool-calling agents that return structured output validated against JSON Schema, reducing malformed responses to under [X%]
  • Built retrieval-augmented generation (RAG) pipelines over [N] documents, including chunking, embeddings, hybrid search and reranking, raising answer accuracy from [X] to [Y] on an internal benchmark

Evaluation and quality4 of 9

  • Set up evaluation-driven development: golden datasets, LLM-as-judge scoring and regression evals in CI, so a prompt or model change ships only if its scores hold
  • Instrumented LLM calls with [Langfuse / OpenTelemetry] tracing to track cost, latency and failure modes per request
  • Wrote rubrics for grading AI output quality and calibrated them across [N] reviewers

Cloud, containers and infrastructure4 of 9

  • Deployed AI services on [AWS / GCP] with Docker and Kubernetes, managed through Terraform
  • Built a model gateway in front of [AWS Bedrock / Azure OpenAI / Vertex AI] with routing, fallback, rate limiting and per-team cost tracking
  • Defined service-level objectives (SLOs) and dashboards covering metrics, tracing and alerting for production AI endpoints

AI coding tools3 of 9

  • Used Claude Code / Codex / Cursor daily in development and set team conventions for agent-assisted work: [review gates, context files, task scoping]

Data pipelines2 of 9

  • Built production data pipelines processing [N TB / N records a day] to prepare training and retrieval data in Python, SQL and [Snowflake / Databricks]
  • Set up data governance for AI platforms: access controls, lineage, and audit trails for model inputs

Client-facing and leadership2 of 9

  • Embedded with [N] enterprise clients as a forward deployed engineer, integrating LLM features with their systems over REST APIs and taking projects from discovery to production
  • Mentored [N] engineers and led technical design reviews for AI platform work

Skills section

Python (async, FastAPI, Pydantic), TypeScript · Anthropic, OpenAI, Bedrock and Vertex APIs · LangGraph, LangChain, OpenAI Agents SDK · RAG, embeddings, vector databases · evals, LLM-as-judge, Langfuse · Docker, Kubernetes, Terraform · AWS, GCP, Azure · SQL, Snowflake, Databricks · Git, CI/CD · Claude Code, Codex, Cursor

Experience: 5 to 6 or more years of software engineering in most. Exceptions: Machinify accepts 2 to 4 years, or a Master's with no industry experience; the G2i contracts want senior-level judgment rather than a set number of years.

Certifications: None of the 9 postings asks for one. Shipped systems and inspectable work (GitHub repos, demos) carry the weight.

What separates candidates: Evaluation work and production deployment. Many candidates have built an agent demo. Fewer can show evals, tracing and uptime for an AI system in production.
